# MK Live Radio Station URL SEO Migration

Date: 2026-07-14

Site: https://mkliveradio.app

## Existing Implementation Summary

- Framework: Next.js 15.5.14 with the App Router.
- Routing: `app/` routes; station pages live at `app/stations/[slug]/page.tsx`.
- Station dataset: `data/stations.json`; production station pages use records where `isVisible !== false`.
- Station rendering: station pages are statically generated with `generateStaticParams()` and render station content in the initial HTML.
- Previous slug behavior: `lib/stations.ts` normalized `name_en ?? name` and appended `-${station.id}`.
- Root cause of numeric suffixes: `getStationSlug()` generated `{normalized-name}-{id}` and `findStationBySlug()` parsed the trailing number to find the station.
- Station IDs: still used internally for the player and app deep links, but no longer used in canonical station page URLs.
- Localization before migration: Macedonian default pages and English station/directory pages via `?lang=en`.
- Localization after migration: homepage uses `/` and `/en`; station directory and station pages preserve the existing low-risk `?lang=en` model with correct canonicals and hreflang.
- Sitemap: generated by `app/sitemap.ts`.
- Robots: generated by `app/robots.ts`.
- Structured data: Organization in layout, WebSite/MobileApplication/FAQ/ItemList on homepage, ItemList/FAQ/BreadcrumbList on directory, WebPage/RadioStation/BreadcrumbList/FAQPage on station pages.
- Redirects: none added, intentionally.

## Slug Strategy

Each station record now has an explicit `slug` field in `data/stations.json`. Public station URLs are built only from that field:

```txt
/stations/{station.slug}
```

Rules enforced by code and tests:

- lowercase ASCII
- single hyphen separators
- no trailing or duplicate hyphens
- no generated array index
- no database ID in station page URLs
- unique across all station records, including hidden records
- hidden records reserve slugs but are not statically generated or included in the sitemap

## Collision Handling

No slug collisions exist in the current 75-record dataset. Meaningful brand qualifiers were used where the repository already supports them through names, logo names, or websites, for example `radio-fortuna`, `radio-marija`, `radio-pela`, `radio-bum`, `radio-orbis`, `radio-orbis-2`, `diamond-radio`, `bravo-radio`, and `galaxy-radio`.

## Canonical and Hreflang

- Macedonian homepage: `https://mkliveradio.app/`
- English homepage: `https://mkliveradio.app/en`
- Macedonian directory: `https://mkliveradio.app/stations`
- English directory: `https://mkliveradio.app/stations?lang=en`
- Macedonian station page: `https://mkliveradio.app/stations/{slug}`
- English station page: `https://mkliveradio.app/stations/{slug}?lang=en`

Each indexable language pair has self-referencing canonical output plus reciprocal `mk`, `en`, and `x-default` alternates.

## Sitemap Changes

`app/sitemap.ts` now includes:

- `/`
- `/en`
- `/stations`
- `/stations?lang=en`
- `/webplayer`
- `/macedonian-radios`
- `/privacy`
- every visible Macedonian station URL
- every visible English station URL

It excludes:

- old numeric station URLs
- hidden stations
- invalid URLs
- player-state URLs such as `/webplayer?id=...`
- `/?lang=en`

The sitemap uses a fixed content revision date of `2026-07-14` instead of current deployment time.

## Robots Changes

`robots.txt` now disallows only `/api/` and no longer disallows `/station`, because that prefix can also block `/stations` for crawlers. It references:

```txt
Sitemap: https://mkliveradio.app/sitemap.xml
```

## Metadata Changes

- Homepage metadata now follows the requested Macedonian and English title/description patterns.
- Station metadata uses:
  - Macedonian: `{Station Name} во живо | MK Live Radio`
  - English: `Listen to {Station Name} Live | MK Live Radio`
- Station descriptions use verified station data and seed data only.
- Open Graph and Twitter metadata use the canonical language URL.
- No metadata should emit `undefined` values.

## Structured Data Changes

- Homepage: `WebSite`, `MobileApplication`, `FAQPage`, and `ItemList`.
- Directory: `FAQPage`, `ItemList`, and `BreadcrumbList`.
- Station pages: `WebPage`, `RadioStation`, `BreadcrumbList`, and `FAQPage`.
- Raw stream URLs are not exposed in station-page JSON-LD.
- `RadioStation` schema uses official station website URLs when present and does not imply MK Live Radio owns third-party stations.

## Homepage Changes

- Added server-rendered Macedonian homepage content with one clear H1.
- Added `/en` English homepage.
- Added links to the station directory, selected station pages, city browsing, web player, iPhone, and Android.
- Added benefits and visible FAQ content.
- Removed unsupported exact station-count claims.

## Station Page Content Changes

- Station pages render visible breadcrumbs.
- Station content is split into conditional sections:
  - About
  - Programming and music format, when verified
  - Frequencies, when verified
  - Listen online
  - FAQ
- Empty headings are not rendered.
- Official websites are rendered as facts, not repeated as generic paragraphs.

## Tests Added

Added `scripts/validate-seo.mjs`, wired to:

```txt
npm test
npm run test:seo
```

The validation checks:

- every station has a slug
- every slug is unique
- every slug matches `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`
- no slug equals the old generated `{normalized-name}-{id}` format
- visible station URLs map to visible station records
- station lookup no longer parses trailing numeric IDs
- station pages call `notFound()`
- alternates, `x-default`, breadcrumbs, and FAQ structured data remain present

## Remaining Recommendations

1. Migrate `next lint` to the ESLint CLI before upgrading to Next.js 16.
2. Add a first-class `genre` or `format` field to `data/stations.json` before creating genre pages.
3. Add unique city intro copy before publishing `/stations/city/{city}` pages.
4. Consider path-based English station routes later, such as `/en/stations/{slug}`, only if the localization layer is intentionally redesigned.
5. Add visual or Playwright smoke tests if station page layout becomes more complex.

## Google Search Console Post-Deployment Checklist

1. Deploy the final clean URL structure.
2. Verify all final station URLs return HTTP 200.
3. Verify numeric station URLs are no longer used internally or included in the sitemap.
4. Verify new URLs have self-referencing canonicals.
5. Resubmit `sitemap.xml`.
6. Inspect `/stations`.
7. Inspect 3-5 important station pages.
8. Inspect one English station page.
9. Use "Test Live URL."
10. Request indexing only for representative pages.
11. Monitor:
    - Discovered, currently not indexed
    - Crawled, currently not indexed
    - Duplicate, Google chose different canonical
    - Soft 404
12. Compare user-declared and Google-selected canonicals.
13. Monitor impressions for the final clean station URLs.
14. Do not reintroduce generated numeric station slugs.
